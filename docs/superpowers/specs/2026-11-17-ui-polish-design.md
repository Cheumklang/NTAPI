# NTAPI — UI polish, batch 1 (design)

**วันที่:** 2026-11-17 · **สถานะ:** รออนุมัติ

## Intent / why
ผู้ใช้ใช้ NTAPI ทุกวันและอยากให้ "เหมือนเดิม แต่สวยขึ้น ดูทันสมัยขึ้น" — ไม่ย้ายตำแหน่ง
ไม่เปลี่ยนพฤติกรรม ไม่แตะสิ่งที่เพิ่งจูนด้วยการวัดพิกเซล (sidebar 305px · กรอบโฆษณา · แถวคิว)
งานนี้จึงเป็น **ชั้นความสวยที่ทับของเดิม** ไม่ใช่การรีดีไซน์

## สิ่งที่ตกลงกันแล้ว (จากบทสนทนา + ม็อกอัป)
1. **สถานะ "AI กำลังทำงาน" = แบบ B "กรอบหายใจ"**
   การ์ดแชทที่เลือกอยู่จะเต้นเป็นจังหวะชีพจร **1.2 วิ** แทนจุดหมุนเล็ก ๆ หน้าชื่อ
   · ไม่ขยับกล่อง/ชื่อ · จบเทิร์นแล้วกลับเป็นกรอบม่วงนิ่ง
   · **รูปทรงจังหวะสำคัญเท่าความเร็ว:** ยอดสว่างอยู่ที่ **22%** ของรอบ แล้วหรี่ลงยาว ๆ
     (รอบแรกใช้ทรงสมมาตร 2.2 วิ — ผู้ใช้ทักว่า "เหมือนเข้มขึ้นเฉย ๆ ไม่มีมิติ"
     เพราะขึ้นช้าเท่าลงช้า ตาไม่ทันจับจุดสว่าง · เลือกแบบชีพจร B จากม็อกอัป 3 จังหวะ)
   · ยอดสว่าง `#baa4ff` .95 + เรืองนอก 20px · หยุดเมื่อ reduced-motion (ค้างฝั่งสว่าง)
   · ทำด้วย `box-shadow` เท่านั้น (ไม่แตะ `border-color`) เพื่อไม่ให้ทับแถบสีที่ผู้ใช้ตั้งไว้
   · แถวที่กำลังทำงานแต่ไม่ใช่แถวที่เปิดอยู่ ยังใช้จุดหมุนในช่องซ้าย
   · (ทางที่พิจารณาแล้วไม่เลือก: A วงหมุนรอบกรอบ · C แถบซ้ายไหล)
2. **Fade ตอนเปิด/ปิด** — หน้าตั้งค่า และเมนู (model picker / เมนูบริบท) จางเข้า ~180ms + เลื่อนขึ้น 4px
   ตอนปิดจางออก ~120ms
3. **ปุ่ม** — hover ยกขึ้น 1px + เงาเรืองจาง · กดจมลง 1px · เปลี่ยนสถานะด้วย transition .12–.18s
4. **รายการ model** — hover แล้วขยาย ~1.035 + ตัวหนาขึ้นแบบนุ่มนวล
   (`cubic-bezier(.2,.8,.3,1)` ~160ms)
5. **Loading** — skeleton วิบวับตอนโหลดประวัติครั้งแรกของแท็บ แทนจอว่าง
6. **Focus** — ทุกปุ่มมีวงแหวนโฟกัสด้วยคีย์บอร์ดที่เห็นชัด (`:focus-visible`)

## Constraints (วัดไว้แล้ว — ห้ามขยับ)
- sidebar ล็อค 305px · กรอบโฆษณา 270×480 (9:16) / 2:1 · ชื่อแชทระนาบเดียวกัน [42,42,42] · แถวคิว 17px
- งานนี้ **ห้ามเปลี่ยน layout/ขนาดกล่อง** — เพิ่มได้แค่สี เงา เส้นขอบ และการเคลื่อนไหว
- ทุกอนิเมชันต้องหยุดเมื่อระบบตั้ง `prefers-reduced-motion: reduce`
- ห้ามแตะ `C:\Program Files\NTAPI\` · ห้ามแตะ NTAPI ADS (คนละโปรแกรม)

## Approaches ที่พิจารณา
- **A) ชั้น CSS ทับ + JS เฉพาะสถานะที่ต้องมี markup (เลือกอันนี้)**
  ความเสี่ยงต่ำสุด · เทสต์วัดพิกเซลเดิมยังใช้ได้ทั้งหมด · ย้อนกลับง่าย (ลบ section ทีหลัง)
- B) รีดีไซน์ทีละคอมโพเนนต์ — สวยได้ไกลกว่า แต่เปิดพื้นที่ที่ผู้ใช้เพิ่งจูน (305px/กรอบโฆษณา) → เสี่ยงหลายรอบ
- C) เปลี่ยน palette/ฟอนต์ทั้งชุด — ขัดกับ "เหมือนเดิม" และเสี่ยงผู้ใช้ไม่ชอบ

## สิ่งที่ผมตัดสินใจแทน (แก้ได้)
- จังหวะกรอบหายใจ: ชีพจร **1.2s** (ยอดที่ 22%) · เรือง `#baa4ff` .95 + นอก 20px
- skeleton เฉพาะการโหลดครั้งแรกของแท็บ ไม่ใช่ทุกครั้งที่สลับแท็บ (กันกระพริบ)
- ตัวเลข easing/ระยะยก ให้ปรับได้ระหว่างทำ ตราบใดที่กล่องไม่ขยับ

## Non-goals
ไม่แตะ ADS · ไม่แตะ palette/typography · ไม่ย้าย/เพิ่มปุ่ม · ไม่แตะข้อความ (i18n)

## เทสต์ที่จะเพิ่ม
- ตรวจว่า element ที่มีอยู่ (การ์ดแชท/ปุ่ม/เมนู) **ขนาดและตำแหน่งไม่เปลี่ยน** หลังเพิ่มชั้นความสวย
- ตรวจว่ามี `prefers-reduced-motion` ครอบทุก animation ใหม่
- เทสต์เดิมทั้งหมดต้องผ่าน: `npm test` · `check:sidebar` · `check-sidebar-note` · `check-sponsor-layout`
  · `check:pill` · `check:queue*` · `check-session-marks`
