# .AGENT — ความจำส่งต่อ session ของ NTAPI

โฟลเดอร์นี้มีไว้เพื่อ **ส่งต่องานข้าม session** ให้ session ใหม่เข้าใจสถานะทันที
โดยอ่านน้อยที่สุด (ประหยัด token)

## ลำดับการอ่านสำหรับ AI
1. **`HANDOFF.md`** ← ไฟล์หลัก อ่านอันเดียวจบ: สถานะ + งานค้าง + ขั้นถัดไป + กติกา
2. `PROJECT.md` — สถาปัตยกรรม/คำสั่ง เทส provider (อ่านเมื่อต้องลงมือลึก)
3. `LOG.md` — ประวัติงาน (ล่าสุดท้ายไฟล์)
4. ไฟล์นี้ — อธิบายระบบความจำเอง (ไม่ต้องอ่านทุก session)

> มี `AGENTS.md` ที่ root ชี้มาที่นี่ เพื่อให้ AI อ่านให้เองเมื่อเปิดโปรเจกต์

## กติกาเหล็ก
- **ห้าม commit/push/tag/PR เอง ต้องขออนุญาตผู้ใช้ก่อน** (ผู้ใช้ใช้ GitHub Desktop)
- commit message ภาษาไทย กระชับ บรรทัดเดียว
- ห้าม commit ไฟล์ runtime (`app/Freepiai/`, `dist/`, credentials)
- ห้ามแตะ `C:\Program Files\NTAPI\` (โปรแกรมที่ติดตั้งจริง) เด็ดขาด — ทดสอบจากซอร์สเท่านั้น
- **ห้ามขยับเลขเวอร์ชันเอง** — เปลี่ยนเมื่อผู้ใช้สั่งเท่านั้น ห้าม tag/release เอง
- **หลังแก้ปัญหาเสร็จทุกครั้ง** — สรุปว่ามีงานค้าง (uncommitted) กี่เรื่อง + ถามว่าจะอัปเวอร์ชันเลยไหม

## โปรโตคอล (สำคัญ — ทำให้ handoff ไม่เน่า)
**ก่อนจบ / ก่อน compact session ทุกครั้ง:**
1. อัปเดต `HANDOFF.md` — หัวข้อ "กำลังทำ/ค้าง" + "ขั้นถัดไป" + วันที่ ให้ตรงความจริงล่าสุด
2. ต่อท้าย `LOG.md` — วันที่, ทำอะไร, ไฟล์ที่แตะ, ผลเทส, สถานะ commit (append-only ห้ามลบเก่า)
3. จด hash ถ้ามีการ commit

**เริ่ม session ใหม่:** อ่าน `HANDOFF.md` → เช็ก `git status` เทียบกับที่เขียนไว้ → ลงมือ
